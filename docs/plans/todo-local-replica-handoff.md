## Research and observed limits

- TinyBase middleware is not a safe pre-relay admission hook: a rejected raw change can still reach other WebSocket peers. `setTablesSchema` does not enforce foreign keys or cycles. Durable Project tombstones plus deterministic accepted projections recover late children, invalid references, and cyclic After rows without hiding raw work. Do not replace this with middleware rejection without a new real-Worker proof.
- An isolated merge and two SQLite clients against the real Worker show that two unobserved edits to one Task text cell converge to one value; the other value disappears. This is **accepted LWW** for same-cell conflicts, not a guarantee for queued writes. The experimental append-only revision layer was removed; do not reintroduce a custom sync protocol without a new decision. Direct raw clients can still write arbitrary cells.
- The phone's complete Waiting/After and recurrence UI behavior, repair actions, and deletion races have not passed the full hermetic Pixel gate. Existing Worker proofs cover several backend cases, including raw clients and Worker restart, but do not prove the full phone UI.
- The old `UserDO` open-list methods omit completed/Done/resolved records. Migration must read every SQL row, retain IDs and all fields, validate references, freeze all legacy mutations, import and verify in the dark, and switch once. There is no cross-DO transaction. Before the switch, incomplete import can be discarded and `UserDO` unfrozen; afterward, fallback writes must continue to `TaskDO`.
- The mobile `zero-app-outbox-v2.sqlite` contains `tx:` entries without dependable account identity. A collection's pending count does not prove that the entire outbox is drained. Inventory every relevant phone and browser outbox, resolve unknown/corrupt actions, and verify server acknowledgments before any real freeze. Keep old device files and frozen server tables as recovery copies.
